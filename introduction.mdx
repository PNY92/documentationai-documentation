## Introduction

Host private SMASH LEGENDS matches by redirecting the official game client to a local ASP.NET Core backend. The private server does not reimplement the combat engine. It uses the client's own embedded dedicated-server implementation for match simulation, while handling authentication, profiles, matchmaking, and rewards through a local HTTP API.

## What is the private server?

The SMASH LEGENDS private server is a Windows-hosted stack with three main components:

- **SmashLegends.Server**: An ASP.NET Core HTTP backend on the default port `18080` with a SQLite database. It handles accounts, JWT sessions, profiles, inventory, matchmaking, lobby management, rewards, and admin operations.
- **SmashLegends.Admin**: An interactive terminal console that calls loopback-only admin APIs to create accounts, manage players, control matches, and back up the database.
- **SmashLegends.Patcher**: A command-line tool, `slpatch.exe`, that generates and verifies SHA-256 manifests, installs `local-config.xml`, and applies a reversible IL patch to the official game executable.

The server targets .NET 10 and uses SQLite through P/Invoke to Windows' `winsqlite3.dll`. It has no external NuGet database dependencies.

## How it works

The client uses the private HTTP backend for meta-game operations and connects directly to the official embedded dedicated-server worker for real-time match simulation.

```text
Game Client
  ├── HTTP → SmashLegends.Server
  │            ├── Accounts and JWT sessions
  │            ├── Profiles, inventory, characters
  │            ├── Master data and feature flags
  │            ├── Lobby and band management
  │            ├── Matchmaking and allocation
  │            └── Admin API (loopback only)
  │
  └── UDP → Official embedded dedicated-server worker
               └── Authoritative Unity match simulation
```

When a match starts, the server launches the official game executable headlessly with `-batchmode -nographics -autoHost` as a dedicated-server worker. The client then connects directly to that worker over UDP for real-time match simulation.

## Current status

<Callout kind="info">

The following features have been verified:

- `local-config.xml` is read by the official client.
- The client reaches the private server.
- Master data is served successfully.
- GamePot and Steam-shaped sign-up works.
- JWT authentication and preference loading work.
- The client reaches the lobby.
- The dedicated-server worker binds its UDP port.
- The server loads the `GameBase` scene.
- The patch is reversible and hash-verified.
- Configuration validation and audit logging work.
- Database backup, restore, and migrations exist.
- Admin routes reject non-loopback peers.

</Callout>

<Callout kind="alert">

The following features are not yet confirmed end-to-end:

- A complete real match through the headless worker path.
- Reliable two-client gameplay.
- Real 3v3 bot filling.
- A completed match with persisted rewards.
- A second consecutive match demonstrating full worker and resource cleanup.

</Callout>
