## Diagnose match worker problems

Match worker issues prevent the private server from launching and completing matches. The worker supervisor launches the official game executable headlessly as a dedicated-server process. Use the diagnostic steps below to identify and resolve common worker problems.

<ExpandableGroup>
<Expandable title="Worker fails to bind UDP port">

The worker supervisor assigns UDP ports from the configured range, which defaults to `30000` through `30010`. If another process already uses the assigned port, the worker cannot bind and the match cannot start.

Check for processes using the worker port range:

```powershell
netstat -ano | findstr :3000
```

- Terminate leftover worker processes.
- Verify that `worker.portMin` and `worker.portMax` are not used by another application.
- Increase the configured port range if you need to run more concurrent matches.

</Expandable>

<Expandable title="Worker crashes on startup">

Check the worker log files in `_work/logs/match-workers/` for the startup error. The supervisor writes a separate log for each match worker.

Check these common causes:

- **Incorrect executable path:** Verify `worker.processPath` and `worker.installDirectory`.
- **Unsupported game build:** Re-verify the installation with `verify-boot-contract.ps1`.
- **Missing IL patch:** Run `apply-dedicated-server-patch.ps1` if the patch was not applied or was reverted.
- **Corrupted game files:** Verify the game files through Steam.

</Expandable>

<Expandable title="Worker loads GameBase but match does not start">

<Callout kind="info">

This issue was resolved by the private match bridge. The bridge injects a private-session boot path that loads the configured map and prepares the roster directly, bypassing the scene transition that previously blocked match initialization.

If you still see this issue, verify that the private match bridge is installed:

- Run `install-private-match-bridge.ps1` to install the bridge.
- Confirm `PrivateMatchBridge.dll` exists in the game's `Managed` directory.
- Check that the patched `Assembly-CSharp.dll` is in place.
- Use `unpatch.ps1` to revert and then reinstall if the patch may be corrupted.

</Callout>

</Expandable>

<Expandable title="Stale or orphaned worker processes">

The supervisor tracks each worker by process ID. If a worker becomes orphaned after a server crash, the supervisor performs the following cleanup when it restarts:

- Reconciles active matches.
- Detects and terminates stale workers.
- Releases match resources.

To manually clean up orphaned workers, run:

```powershell
Get-Process -Name "Smash_Legends" -ErrorAction SilentlyContinue | Stop-Process -Force
```

</Expandable>

<Expandable title="Worker logs show no client connection">

If the worker starts but no client connects, check the advertised address and the allocated connection details.

- Verify that `advertised.address` in `server-config.json` matches an address reachable by the client.
- Confirm that the client received the correct IP address and port in the match allocation.
- Verify firewall rules allow UDP traffic on the worker port range.
- Check that the client is connecting to the intended server.

</Expandable>

<Expandable title="Second match fails to allocate">

Each match requires a unique UDP port from the worker range. If the first worker does not release its port, the next match may remain unallocated.

- Confirm that the supervisor detected and terminated the stale worker.
- Check `match.maxConcurrentMatches`. The default value is `1`.
- Verify that the previous match's worker stopped successfully.
- Use the admin console command `match stop` to force-stop a stuck match.

</Expandable>

<Expandable title="Worker process not found">

If the supervisor cannot find the game executable, verify the worker configuration and installation path.

- Confirm that `worker.processPath` points to `Smash_Legends.exe`.
- Confirm that `worker.installDirectory` points to the correct Steam installation directory.
- Verify that `worker.enabled` is `true`.
- Check that the executable exists at the configured path.

</Expandable>

<Expandable title="Mock host match fails to start">

When `matchHost.kind` is set to `mock`, the server uses an in-process host instead of spawning a game worker. If a mock match fails to start, check:

- Confirm `matchHost.kind` is set to `mock` in `server-config.json`.
- Verify that the mock host port range (`matchHost.mockPortMin` through `matchHost.mockPortMax`) is not already in use.
- Check that the mock host tick rate (`matchHost.mockTickHz`) is set to a positive integer.
- Mock matches require exactly two teams and three capture zones. Other configurations are rejected.
- The official game client cannot connect to mock-hosted matches. Use a mock client that sends JSON UDP packets instead.

Use `POST /api/mock/allocate` to create a mock match and `POST /api/mock/stop?matchId=<match-id>` to stop it.

</Expandable>
</ExpandableGroup>
